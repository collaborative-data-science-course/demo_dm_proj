# What are `.gitignore`, `requirements.txt`, and `.env` Files?

In most Python and data science projects, you’ll find files like `.gitignore`, `requirements.txt`, and `.env` in the root directory. Each of these files plays a specific role in organizing, protecting, and sharing your project effectively.

---

## `.gitignore` – Ignore Files from Git Tracking

### What it does
Specifies which files or folders Git should ignore. These files will not be tracked, committed, or pushed to GitHub.

### Why use it
- Prevents committing sensitive or large files
- Keeps the repository clean from unnecessary or auto-generated files
- Avoids platform-specific clutter (e.g., OS or IDE files)

### Example `.gitignore`:

```py
# Byte-compiled / cache files
pycache/
*.py[cod]

# Virtual environment
venv/

# Environment variables
.env

# Data or model files
data/
models/

# Jupyter Notebook checkpoints
.ipynb_checkpoints/

# OS and editor-specific files
.DS_Store
.vscode/
```

## `requirements.txt` – Python Dependency File

### What it does
Lists all Python packages and specific versions your project needs. Used by pip to install all dependencies.

### Why use it
- Makes it easy for others to replicate your environment
- Ensures compatibility and reproducibility
- Simplifies deployment and testing

### Example `requirements.txt`:

```py
pandas==2.2.1
scikit-learn==1.4.1
numpy>=1.25
matplotlib
dvc[gdrive]
mkdocs-material
```


### How to install packages from it:

```bash
pip install -r requirements.txt
```

### Generate requirements.txt from current environment:

```bash
pip freeze > requirements.txt
```

---

## `.env` – Environment Variables File

### What it does

Stores sensitive configuration values like API keys, secret keys, and database URLs in a secure and environment-specific file.

### Why use it

- Keeps sensitive information out of source code
- Allows easy switching between development, staging, and production environments
- Works well with packages like python-dotenv to load values automatically

Example .env:

```
SECRET_KEY=supersecret123
DATABASE_URL=sqlite:///mydb.sqlite3
DEBUG=True

```

### Important:

Always add `.env` to `.gitignore` so that it doesn't get committed to your repository.

---

## Summary Table

| File               | Purpose                                         | Should be committed to Git? |
| ------------------ | ----------------------------------------------- | --------------------------- |
| `.gitignore`       | Tells Git which files/folders to ignore         | Yes                         |
| `requirements.txt` | Lists all Python dependencies for the project   | Yes                         |
| `.env`             | Stores secret or environment-specific variables | No (add to `.gitignore`)    |
