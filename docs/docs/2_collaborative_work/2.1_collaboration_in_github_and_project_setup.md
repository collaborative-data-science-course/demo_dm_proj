# Collaboration Using GitHub

GitHub isn’t just a place to host your code — it’s a powerful collaboration platform where teams can work together efficiently. In this section, you'll learn how to **invite collaborators**, **set up a project board**, and **use milestones and issues** to manage tasks.

---

## Inviting People to Your GitHub Repository

To collaborate with others:

1. Go to your repository on GitHub.

2. Click on the **"Settings"** tab.

3. Navigate to **"Collaborators & teams"** (under "Access").

4. Click **"Invite a collaborator"**.

5. Enter the GitHub username or email and click **Add**.

> You need to have at least **Write** access to invite collaborators.

---

## Setting Up a GitHub Project Board

Project boards help you visually organize tasks using **columns and cards**, similar to a Kanban board.

### Steps to Create a Project Board:

1. In your repo, click on the **"Projects"** tab.

2. Click **"New project"** → Choose **"Board" view**.

3. Give it a name (e.g., "Website Redesign") and description.

4. Choose **Repository** or **Organization** visibility.

5. Add columns like:
      - `To Do`
      - `In Progress`
      - `Done`

### Adding Issues or Notes to the Board:

- Click **“+”** on a column to add an issue or note.
- Drag and drop to move between columns.

> Tip: Boards help track team progress during sprints or milestones.

## Creating Milestones

Milestones are used to group related issues and track progress toward a larger goal (like a release).

### Steps:

1. Go to the **"Issues"** tab.

2. Click **"Milestones"** → **"New milestone"**.

3. Add:
      - A title (e.g., `Version 1.0`)
      - Description (optional)
      - Due date (to keep the team on track)


4. Click **Create milestone**.

> You can associate issues or pull requests with a milestone to visualize progress.

---

## Creating and Managing Issues

Issues are how you report tasks, bugs, or feature requests.

### To Create an Issue:

1. Go to the **"Issues"** tab.

2. Click **"New Issue"**.

3. Add:

      - A **title** (e.g., “Fix login button”)
      - A **description**
      - Labels (like `bug`, `feature`, `help wanted`)
      - Assignees (who will work on it)
      - Milestone (optional)

4. Click **Create new issue**.

---

## Labels, Assignees, and More

- **Labels**: Color-coded tags (e.g., `bug`, `documentation`, `frontend`) to categorize issues.
- **Assignees**: Assign team members to specific issues.
- **Linked Pull Requests**: GitHub will automatically link PRs that close an issue using keywords like:
  
```
  Closes #42
  Fixes #10
  Resolves #5
```

## Example Workflow

1. Create a milestone.
2. Add related issues (e.g., fix bugs, add login feature).
3. Organize issues in a project board.
4. Assign collaborators to issues.
5. Track progress visually and via milestone completion.
