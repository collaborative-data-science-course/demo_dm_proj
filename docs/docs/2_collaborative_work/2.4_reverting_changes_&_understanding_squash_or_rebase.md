# Reverting Changes & Understanding Squash/Rebase in Pull Requests

While working with Git and GitHub, there will be times when you need to go back to a previous version, clean up commit history, or collaborate more effectively in pull requests. This guide explains how to **revert work**, and the difference between **squash** and **rebase**.

---

## Revert to a Previous Commit

Sometimes, you might want to undo your recent changes and go back to a stable state.

### Using `git log` to find the commit:

```bash
git log
```
This shows a list of past commits with hashes like:

```commit a1b2c3d4e5...
Author: Jane Doe
Date: ...
    Fix layout bug
```
---

### Revert the commit (non-destructive):

```bash
git revert a1b2c3d4e5
```

This creates a new commit that undoes the changes from that specific commit. It's safe for shared branches (like `main`).

---

## Reset (More aggressive & not safe on shared branches)

```bash
git reset --hard <commit-hash>
```

This moves your branch pointer and working directory back to a specific commit. Use this only on your local branches that haven’t been pushed.

---

## Squash Commits (Combine multiple commits into one)

When your pull request has many small or messy commits (e.g., “fix typo”, “update again”), you can squash them into a single clean commit before merging.

### How to Squash in GitHub:

1. Open your Pull Request.
2. Click the dropdown next to Merge pull request.
3. Choose Squash and merge.
4. Edit the final commit message (optional).
5. Confirm the merge.

### Example:

Before squashing:

```
commit A - Add navbar
commit B - Fix typo in navbar
commit C - Add dark mode toggle
```

After squashing:

```
commit Z - Add navbar and dark mode toggle (all in one)
```

Squashing is great for cleaning history in main or production branches.

---

## What is Rebase?

Rebase lets you reapply your branch commits on top of another branch, giving you a linear commit history.

### Example:

You have:

```
main:    A---B---C
feature:         D---E
```

After rebasing `feature` onto `main`:

```
main:    A---B---C---D'---E'
```

This is useful when you want to "catch up" with the latest changes on `main` before merging.

```bash
git checkout feature
git rebase main
```

---

## Squash vs Rebase vs Merge

| Method     | Use Case                                   | Resulting History         |
| ---------- | ------------------------------------------ | ------------------------- |
| **Merge**  | Standard way to combine branches           | Keeps full commit history |
| **Squash** | Clean up before merging (1 clean commit)   | One commit only           |
| **Rebase** | Replay changes linearly (no merge commits) | Linear, clean history     |

---

### Summary

1. Use `git revert` to undo changes safely.
2. Use Squash and Merge in PRs to keep history clean.
3. Use Rebase to sync branches and avoid merge commits.
