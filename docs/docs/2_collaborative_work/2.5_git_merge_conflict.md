# Resolving Merge Conflicts

---

##  What is a Merge Conflict?

A **merge conflict** happens when Git cannot automatically merge changes because:

- Two branches have **edited the same line** in the same file
- One branch **deleted a file** the other one modified

Git needs your help to **choose which version** to keep.

---

## Example Scenario

Let’s say you and a teammate both edit `app.py`:

**You** (`main`):
```python
print("Welcome to the app")
```

**Teammate** (`feature/change-msg`):

```bash
print("Hello from feature branch")
```
When you try to merge their branch into yours — Git doesn't know which version to keep.
This is a merge conflict.

---

## Let's Simulate a merge conflict and resolve it.

### Step 1: Start from clean main

```bash
git checkout main
git pull origin main
```

### Step 2: Create and edit a feature branch

```bash
git checkout -b feature/conflict-demo
echo 'print("Hello from feature branch")' > app.py
git add app.py
git commit -m "Edit app.py in feature branch"
git push origin feature/conflict-demo

```

### Step 3: Simulate conflicting change in `main`

```bash
git checkout main
echo 'print("Welcome from main branch")' > app.py
git add app.py 
git commit -m "Edit app.py in main"
git push origin main

```

### Step 4: Merge conflict happens!

Try merging:

```bash
git checkout main
git merge feature/conflict-demo

```

You’ll see:

```bash
CONFLICT (content): Merge conflict in app.py
Automatic merge failed; fix conflicts and then commit the result.

```

## Understanding Git Merge Conflict Markers

When Git can't automatically merge two versions of a file, it modifies the file and adds conflict markers like this:

```bash
<<<<<<< HEAD
print("Hello from the main branch")
=======
print("Hello from the feature branch")
>>>>>>> feature/my-feature

```

Let’s break it down:

- `<<<<<<< HEAD`: This is the current branch’s version (where you ran the merge, usually main)
- `=======`: This line separates the two conflicting versions
- `>>>>>>> feature/my-feature`: This is the incoming version from the branch you're trying to merge (`feature/my-feature`)

Git is saying:

> "Hey! I don’t know which version to keep — you changed this part in both branches. Please help me decide."

---

## How to Resolve the Conflict (Step-by-Step)

Let’s say your file app.py has a conflict that looks like this:

```bash
print("Program started")

<<<<<<< HEAD
print("Hello from the main branch")
=======
print("Hello from the feature branch")
>>>>>>> feature/greeting-update

print("Goodbye")

```
### Step 1: Open the file

Open app.py in your favorite code editor (VS Code, Atom, Sublime, or even Notepad).

### Step 2: Decide What Should Stay

You now have three choices:

**Option A: Keep the `main` version**

```bash
print("Program started")
print("Hello from the main branch")
print("Goodbye")

```

**Option B: Keep the feature version**

```bash
print("Program started")
print("Hello from the feature branch")
print("Goodbye")

```

**Option C: Combine them manually**

```bash
print("Program started")
print("Hello from the main branch")
print("Hello from the feature branch")
print("Goodbye")

```

---

### Step 3: Remove the Conflict Markers

Delete the following lines:

- `<<<<<<< HEAD`
- `=======`
- `>>>>>>> feature/greeting-update`

You should be left with clean, valid code.

---

### Step 4: Stage and Commit the Resolved File

```bash
git add app.py
git commit -m "Resolve merge conflict in app.py"

```

---

### Step 5: Push the Changes

```bash
git push origin main
```

Or if you were resolving it inside a PR on GitHub, it will automatically update the PR with your resolution.

---

## Important Tips

| Mistake                           | Fix                                                        |
| --------------------------------- | ---------------------------------------------------------- |
| Leaving conflict markers in code  | Always remove `<<<<<<<`, `=======`, `>>>>>>>`              |
| Not testing after resolution      | Run the code to ensure nothing broke                       |
| Forgetting to commit after fixing | `git add` and `git commit` must follow conflict resolution |


---

## Tips to Prevent Conflicts

- Pull frequently (git pull origin main)
- Communicate with your team
- Keep feature branches short-lived
- Don’t make large unrelated changes in one PR
- Use clear commit messages
