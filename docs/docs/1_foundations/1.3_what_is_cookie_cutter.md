# Setting Up Cookiecutter Data Science

## Objective

This module helps you understand what Cookiecutter Data Science (CCDS) is, why it's useful in team-based ML projects, and how to set it up for your own project.

---

## What is Cookiecutter Data Science?

Cookiecutter Data Science (CCDS) is a project template that helps you organize your data science workflows in a modular, scalable, and team-friendly way.

It provides a clean structure for:

- Managing raw and processed data
- Organizing notebooks, scripts, and models
- Separating config, pipelines, and reports
- Collaboration using Git and version control

It’s ideal when multiple people are working on:

- Data ingestion
- Feature engineering
- Modeling
- Reporting and inference

---

## CCDS Folder Structure Overview

Here’s a simplified version of the standard folder layout:

```
project-name/
│
├── data/
│   ├── raw/         # Untouched original data
│   ├── interim/     # Temporary data
│   ├── processed/   # Final data used for modeling
│   └── external/    # External data sources
│
├── notebooks/       # Jupyter notebooks (exploration, EDA, experiments)
├── models/          # Trained models (Pickle files)
├── reports/
│   ├── figures/     # Visualizations and images
│   └── *.txt        # Evaluation summaries, notes
│
├── {{ cookiecutter.module_name }}/
│   ├── config.py    # Configuration paths
│   ├── dataset.py   # Data ingestion
│   ├── features.py  # Feature processing
│   ├── modeling/    # train.py, predict.py
│   └── plots.py     # Visualization code
│
├── Makefile         # Automation for pipeline
├── requirements.txt # Dependencies
├── README.md        # Project overview
└── .env             # Environment variables

```

## How to Set Up Cookiecutter Data Science

### Step 1: Install `cookiecutter`

If you haven’t already installed Cookiecutter:

```bash
pip install cookiecutter-data-science
```

### Step 2: Use the CCDS Template

Run this command to generate a new project:

```bash
# From the parent directory where you want your project
ccds
```

You’ll be prompted to answer questions like:

- Project name
- Author name
- Python package name
- etc.

After this, a project folder is generated with the complete template.

---

## What to Do After Setup

Once the template is created:

1. Create a virtual environment and activate it
2. Install necessary dependencies
3. Start developing in your modules like `dataset.py`, `features.py`, `train.py`, etc.
4. Initialize a Git repo and push it to GitHub

```bash
cd project-name/
python -m venv venv
source venv/bin/activate   # or venv\Scripts\activate on Windows
pip install -r requirements.txt
git init
git remote add origin <your-repo-url>
git add .
git commit -m "Initial commit"
git push -u origin main
```

## Why Use CCDS?

- Enforces a clean separation between different phases of a data science pipeline
- Enables collaborative development with multiple contributors
- Helps in maintaining reproducibility and automation using `Makefile`
- Works well with version control and CI/CD pipelines
